# DiscoJ · 디스코제이

Discord에서 실제 공용 YouTube 재생목록을 관리하는 사내용 봇입니다.
Python + discord.py를 사용하며 프론트엔드, WebSocket, 재생 대기열은 없습니다.
음악은 맥미니의 YouTube 재생목록 페이지에서 직접 재생합니다.
자동 폴백, 현재 재생곡 감지, 봇 재생 상태 표시는 제공하지 않습니다.

## 명령어

| 명령어 | 기능 |
| --- | --- |
| `/추가 링크` | 유튜브 영상 하나를 목록에 추가. 실제 목록 조회 후 중복 검사 |
| `/목록` | 본인에게만 고정 번호·영상 제목을 5곡씩 표시. 새로고침으로 같은 메시지 갱신, 하단에 재생목록 보기 버튼 제공 |
| `/현재곡` | 연결된 유튜브 탭의 영상 제목·링크를 본인에게만 표시 |
| `/삭제 번호` | 번호 직접 입력 또는 영상 제목 자동완성 → 제목 확인 후 삭제/취소. 원본 영상은 유지 |

- Petasona 서버 `1526382640230432858`의 `#디스코제이` 채널 `1560519100021608598`에서만 실행합니다.
- 개인 제한은 없습니다. 현재 목록 최대 90곡을 기본값으로 사용하며 `MAX_PLAYLIST_SIZE`로 변경할 수 있습니다.
- 90곡은 **현재 곡 수 제한**이며 일일 추가 횟수나 API 할당량 보장은 아닙니다. 반복 추가·삭제도 할당량을 소비합니다.
- 자동 일일 삭제/초기화는 하지 않습니다. 팀원이 필요할 때 정리합니다.
- 추가·조회·삭제는 하나의 asyncio.Lock에서 순차 처리하며 목록 캐시는 유지하지 않습니다. YouTube 조회 반영 지연에 대비해 방금 성공한 추가 항목은 60초 동안 기억하여 연속 중복을 막습니다.
- 지정 채널에서는 누구나 곡 번호로 모든 곡을 삭제할 수 있습니다. 추가한 사람이나 Discord 역할을 검사하지 않습니다.
- 번호는 삭제 후 바뀌므로 `/삭제`는 `/목록`이 알려주는 **재생목록 항목 ID**를 사용합니다. 영상 ID와 다릅니다.
- 유튜브에서 사람이 동시에 편집하는 것까지 원자적으로 처리할 수는 없습니다. 봇 전용 목록 사용을 권장합니다.
- API 한도 초과를 감지하면 태평양 시간 날짜가 바뀔 때까지 추가 호출을 차단합니다. 재시작 시 차단 상태도 초기화됩니다.
- 통신 실패 후 쓰기 요청은 자동 재시도하지 않습니다. 성공 여부가 불확실하면 `/목록`으로 확인하세요.
- 예전 `/내추천`, `/도움말`은 시작 시 지정 서버의 명령어 동기화에서 제거됩니다.

## 실행

Python 3.9 이상, Docker에서는 3.12 사용.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env  # 기존 .env가 있다면 덮어쓰지 말고 새 항목만 추가
python -m discoj.main
```

필수 설정: `DISCORD_TOKEN`, `DISCORD_GUILD_ID`, `DISCORD_CHANNEL_ID`.
유튜브 설정이 비어 있어도 봇은 연결되지만 명령어는 연동 설정 필요 안내를 반환합니다.
`EXCLUDED_USER_IDS`에는 lab4dx의 숫자 사용자 ID를 지정하세요.
토큰·클라이언트 시크릿·리프레시 토큰은 `.env`에만 저장하고 커밋하지 마세요.
기존 `PLAYER_ORIGIN`, `FALLBACK_VIDEO_ID`, `MAX_QUEUE_SIZE`는 더 이상 사용하지 않습니다.

## YouTube 인증 (운영 전 필수)

1. 관리용 Google 계정으로 전용 YouTube 재생목록을 만듭니다. 다른 직원도 열 수 있도록 공개 범위를 선택합니다.
2. Google Cloud 프로젝트에서 YouTube Data API v3를 활성화합니다.
3. Google Auth Platform 동의 화면과 **데스크톱 앱 OAuth 클라이언트**를 만듭니다.
4. `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `YOUTUBE_PLAYLIST_ID`를 `.env`에 넣습니다.
5. 아래 인증 도구를 설치하고 실행합니다. 재생목록 소유 계정으로 `youtube` 스코프 권한을 승인합니다.

```sh
pip install -r requirements-auth.txt
python -m discoj.authorize
```

도구는 토큰을 출력하지 않고 `.env`의 `GOOGLE_REFRESH_TOKEN`에 저장합니다. 로컬 콜백 포트는 자동 선택합니다.
Google 앱이 External/Testing이면 YouTube 권한의 리프레시 토큰은 일반적으로 7일 후 만료될 수 있습니다. 장기 운영은 브랜딩 문서 링크 설정 → 프로덕션 게시 → 위 인증 도구로 재인증 순서로 구성하세요. 프로덕션 전환은 Google 검증 심사와 별개이며 토큰 철회 등 다른 만료 사유는 남습니다.

현재 운영 프로젝트는 프로덕션 전환과 재인증을 완료했습니다(2026-10-22). 공개 안내 문서는 [서비스 소개](docs/index.md), [개인정보처리방침](docs/privacy.md), [이용 안내](docs/terms.md)에 있습니다.

## 검증

```sh
pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
```

테스트는 공식 응답 구조를 바탕으로 만든 로컬 상태 유지 HTTP 모의 Google/YouTube 서버를 사용합니다.
실제 HTTP 클라이언트·페이지네이션·OAuth 토큰 캐시·동시 중복 방지·삭제 권한·할당량 차단을 검증하며 실제 Google 권한 검증을 대체하지 않습니다.
Postman CLI가 이 환경에 없어 로컬 aiohttp 테스트 서버를 사용합니다.
실제 추가·삭제는 Google 인증 후 별도 확인이 필요합니다.

곡 번호는 삭제 후 재사용하지 않습니다. 번호와 YouTube 항목 ID 연결만 `data/track-numbers.json`에 보관하며 Docker의 `discoj_data` 볼륨으로 재시작 후에도 유지합니다. 이 파일이나 볼륨을 삭제하면 번호 기록이 사라지므로 보존해야 합니다. 추천자 정보는 저장하지 않습니다.

`/추가`, `/목록`, `/삭제`, `/현재곡`의 성공 및 오류 응답은 명령을 실행한 사람에게만 표시됩니다.

### 삭제 및 운영 정책

- 영상 길이는 제한하지 않습니다.
- 삭제 자동완성은 번호·영상 제목을 검색하며 최대 25개를 표시합니다. 후보 조회는 30초간 캐시하고, 실제 삭제 전에는 유튜브 목록을 다시 확인합니다.
- 삭제 확인은 본인에게만 표시되며 2분간 사용할 수 있습니다. 취소 또는 중복 클릭은 추가 삭제를 발생시키지 않습니다.
- 목록은 5곡씩 표시하며 새로고침은 현재 페이지를 유지합니다. 해당 페이지가 없어지면 마지막 페이지로 이동합니다. 목록 조작 버튼은 5분간 사용할 수 있으며 이후 `/목록`을 다시 실행하세요.
- `quotaExceeded` 또는 `dailyLimitExceeded` 응답 시 태평양 시간 다음 자정까지 요청을 차단합니다. `data/quota-state.json`을 같은 Docker 볼륨에 저장해 재시작 후에도 유지하며, 초기화 시각 이후 첫 요청에서 자동 해제됩니다. 안내에는 한국 시간 해제 시각을 표시합니다.
- 차단·연결 오류 중에도 유튜브 재생목록 보기 버튼을 제공합니다. 번호 파일 백업은 추가하지 않았습니다.

### 현재 재생 영상 연결 (Chrome 확장)

`/현재곡`은 연결된 유튜브 탭의 영상 제목과 링크를 실행한 사람에게만 보여줍니다. 일시정지는 구분해서 표시하며, 연결 종료 또는 마지막 보고 후 45초가 지나면 재생 정보를 확인할 수 없다고 안내합니다. 긴 영상 내부의 개별 곡은 추적하지 않습니다. YouTube API를 사용하지 않습니다.

1. `.venv/bin/python scripts/prepare_extension.py`로 설치용 사본을 생성합니다. 로컬 인증 키는 `.env`와 git에서 제외된 `data/browser-extension/config.js`에만 저장됩니다.
2. `docker compose up -d --build`로 봇을 실행합니다.
3. Chrome의 `chrome://extensions`에서 개발자 모드를 켜고 압축해제된 확장 프로그램 로드로 `data/browser-extension` 폴더를 선택합니다. 인증 키가 들어 있는 설치용 폴더는 공유하지 마세요.
4. 유튜브 탭을 새로고침하고, 확장 아이콘의 **이 탭 연결**을 누릅니다. 여러 유튜브 탭이 있어도 선택한 탭만 사용합니다. 탭을 바꾸려면 새 탭에서 다시 연결합니다. 브라우저 재시작 후에도 다시 연결하세요.
5. Discord의 지정 채널에서 `/현재곡`을 실행합니다.

이 기능의 HTTP 수신 주소는 맥미니의 `127.0.0.1:18766`이며 Bearer 인증 키로 보호됩니다. 확장과 봇 사이에 영상 제목·영상 ID·재생 상태·음량을 전달하며 서버에는 메모리로만 보관합니다. Discord Activity 화면은 별도의 사용자 인증 API를 이용합니다.

### 재생 중 목록 자동 반영

연결한 유튜브 `/watch?...&list=공용목록ID` 탭에 확장이 **DiscoJ 목록**을 표시합니다. 유튜브 서버 목록은 기존 API로 변경하며, 브라우저에서는 기본 목록 패널을 잠시 숨기고 확장이 최신 목록을 표시합니다. 유튜브의 비공개 플레이어 상태를 직접 변경하지 않습니다.

- 봇에서 성공한 추가·삭제는 약 5초 간격으로 화면에 반영합니다. 브라우저의 로컬 목록 확인은 YouTube API를 추가 소모하지 않습니다.
- 목록 갱신 시 영상 로드·일시정지·탐색을 호출하지 않습니다. 현재 영상을 삭제해도 재생은 유지합니다.
- 영상의 자연 종료 또는 다음/이전 조작 시 최신 순서를 사용합니다. 현재 영상이 제거된 경우 마지막으로 확인한 위치 다음의 남은 곡부터 진행합니다. 마지막 곡이면 자동 반복하지 않습니다.
- 확장의 목록 버튼 및 플레이어 다음/이전 버튼, Shift+N/P에 적용합니다. 브라우저 연결이 끊기면 마지막 확인 목록임을 표시합니다.
- 목록 자동 동기화는 봇으로 추가·삭제한 항목에 적용합니다. 유튜브에서 직접 편집한 변경은 Discord `/목록` 조회·새로고침 시 봇에도 반영됩니다.
- 확장을 연결 해제하면 원래 유튜브 목록 패널을 다시 표시합니다. 플레이어 자체는 유지됩니다. 새 확장은 연결 시 페이지를 새로고침하지 않고 적용할 수 있습니다.

### 재생 버튼으로 연결 복구

확장 1.7.0부터 30초 주기 자동 탭 복구를 제거했습니다. 재생 버튼을 누르면 기존 재생 탭을 먼저 찾아 재연결하고, 이미 재생 중이면 영상을 이동하거나 다시 재생하지 않습니다. 선택 정보가 없으면 소리가 나는 유튜브 탭, 마지막 연결 주소, 공용 재생목록 탭 순서로 찾습니다. 여러 탭에서 소리가 나면 확장에서 사용할 탭을 선택하도록 안내합니다. 재생목록 탭이 없을 때만 하나를 열며 동시 요청은 합칩니다.

Chrome이 종료되어 있으면 맥미니의 로컬 실행 도우미가 회사 계정 프로필(`Default`, Lab4DX)을 열고 확장이 공용 재생목록을 연결합니다. `.venv/bin/python scripts/install_host_launcher.py`로 로그인 사용자 LaunchAgent를 설치합니다. 이 설치는 `.env`에 서버 전용 `HOST_LAUNCH_TOKEN`과 `~/Library/Application Support/DiscoJ/host-launcher.json`을 만들며, 호스트 `127.0.0.1:18769`의 인증된 고정 기능만 제공합니다. 임의 명령이나 외부 URL은 받지 않습니다. 맥미니 사용자가 로그인해 있고 컴퓨터가 깨어 있어야 하며, 유튜브 로그인/자동재생 차단은 화면에서 해결해야 합니다.

확장과 봇 사이에는 인증된 WebSocket 연결과 20초 연결 확인만 유지합니다. 이는 자동 탭 복구나 YouTube Data API 호출이 아닙니다. 회사 프로필이나 확장을 변경했다면 로컬 도우미 설정과 확장 설치를 함께 확인하세요.

### 재생 연결 복구 정책

- 곡 종료 및 다음/이전 선택 시 최신 목록을 다시 확인한 후 이동합니다. 연결이 끊기면 현재 영상은 그대로 두고, 최신 목록 확인 전에는 자동 다음 곡으로 이동하지 않습니다.
- 마지막 곡 종료 후 새 곡이 반영되면 자동으로 이어갑니다. 사용자가 일시정지하거나 다른 영상으로 이동한 경우에는 강제로 재생하지 않습니다.
- 목록 요청은 연결별로 한 번에 하나씩 처리하고, 재연결 이전 응답은 폐기합니다.
- 선택한 탭의 현재 영상과 그 앞에 있던 영상 ID를 확장 로컬 저장소에 보관합니다. 현재곡 삭제 후 재연결해도 다음 위치를 복원하며, 위치 정보가 없으면 앞의 곡을 임의로 다시 틀지 않습니다.
- 이 위치 기록에는 사용자 ID·인증 정보·전체 브라우징 기록을 저장하지 않습니다. 선택한 탭을 닫으면 위치 기록을 지웁니다.

구버전 확장을 재생 중 교체할 때 남아 있는 이전 스크립트는 플레이어를 다시 불러오지 않고 비활성화합니다. 이때 현재 탭 주소의 `list`가 임시 `discoj_list`로 바뀔 수 있으며, 다음 영상으로 이동하면 표준 유튜브 재생목록 주소로 복귀합니다.

### 음악 컨트롤

공용 재생목록은 전체 반복이 기본입니다. 마지막 곡이 끝나면 최신 메모리 목록의 첫 곡으로 돌아가며, 한 곡만 있으면 그 곡을 다시 재생합니다. 빈 목록에서는 대기하고 수동 일시정지는 유지합니다. 목록에서 제거된 현재곡은 끝까지 재생한 뒤 남은 다음 곡 또는 첫 곡으로 이동합니다. 반복 순서 계산에는 YouTube API를 호출하지 않습니다. 이 동작은 확장에 연결된 공용 재생목록 탭에 적용되며, 재생목록 밖에서 따로 연 영상에는 적용하지 않습니다.

`/컨트롤`은 실행한 사람에게만 조작 패널을 표시합니다. 누구나 사용할 수 있으며, 조작은 사무실의 연결된 유튜브 탭에 적용됩니다.

- 이전 영상 재생 / 다음 영상 재생 / 재생 일시정지 / 재생 시작
- 유튜브 음량 −10% / +10%, 또는 **유튜브 음량 설정**에서 0~100% 직접 입력
- 상태 새로고침, 5분 후 패널 만료

음량 조절은 유튜브 미디어 요소만 변경하며 macOS 시스템 음량은 변경하지 않습니다. 따라서 유튜브가 이미 100%라면 더 크게 하려면 맥미니/스피커 음량을 직접 올려야 합니다. 재생 요청은 브라우저 확인 응답을 기다리며, 다음/이전 영상은 최신 목록을 확인한 뒤 이동 요청을 전달합니다. 오류·연결 끊김·응답 시간 초과를 성공으로 표시하지 않습니다. 조작 요청은 재시작 시 폐기하며 중복 자동 재시도하지 않습니다.

### Discord Activity

Discord 앱 메뉴의 **디스코제이 → 실행**으로 전용 화면을 엽니다. 현재곡, 재생 상태, 메모리 기반 재생목록을 자동 갱신하고 이전곡·다음곡·재생·일시정지·유튜브 음량을 조절합니다. 목록 제목을 누르면 맥미니의 연결된 유튜브 탭에서 해당 곡을 재생합니다. 목록 밖 영상을 수동으로 듣다가도 목록 곡을 선택하면 공용 재생목록으로 전환됩니다. 유튜브 링크 입력으로 곡을 추가할 수 있으며, 추가만 할 때는 현재 음악을 유지합니다. 목록의 삭제 버튼을 누르면 곡 제목을 확인한 뒤 삭제하거나 취소할 수 있습니다. Activity에서는 번호를 숨기며, `/삭제`에서 사용하는 고정 번호는 그대로 유지합니다. `/추가`와 `/삭제`도 계속 사용할 수 있습니다.

재생 상태는 인증된 스트림으로 모든 Activity에 변경이 있을 때만 전달합니다. 변경이 없으면 15초마다 연결 확인만 보내고, 재접속 시 최신 상태를 즉시 전달합니다. 누가 조작하든 실제 유튜브 탭의 상태를 표시하며, 이전 조회가 늦게 도착해 최신 상태를 덮어쓰지 않도록 합니다. 스트림은 유튜브 API를 호출하지 않습니다. Discord가 백그라운드 화면을 중단한 경우에는 화면으로 돌아오면 다시 갱신합니다.

사용자는 Discord 기본 프로필 인증 후 지정 서버의 디스코제이 채널 접근 권한을 확인받습니다. 재생 제어는 사무실의 공용 재생 탭에 적용됩니다. 인증은 최대 8시간 유효하며 봇을 재시작하면 다시 연결해야 합니다. [Activity 실행 설정](activity/README.md)과 [API 계약](docs/activity-api.md)을 참고하세요. 현재 테스트용 터널을 사용하므로 상시 운영 전에는 고정 HTTPS 주소가 필요합니다.

지정 음악 채널에는 **디스코제이 열기** 버튼이 있는 안내 메시지를 고정합니다.
버튼은 Discord의 Activity 실행 응답을 사용하며, 봇 재시작 후에도 작동합니다. 안내 메시지는 자동으로 고정하지 않습니다. 기존 Activity 카드의 고정 상태는 사용자가 관리합니다.
안내 메시지 ID는 `data/activity-launcher.json`에 보관해 재연결 시 같은 메시지를
갱신합니다. 봇에 메시지 전송·기록 조회·메시지 고정 권한이 필요합니다.
